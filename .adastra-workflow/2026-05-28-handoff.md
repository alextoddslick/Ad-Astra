## Code fixes (Ad Astra)

All landed in commit `e43018ca` on `26.1.2-fabric` (pushed to origin).

### Gravity normalizer / oxygen distributor — `onRemoved` never fired
- **File:** `fabric/src/main/java/earth/terrarium/adastra/common/blockentities/base/MachineBlockEntity.java`
- **Symptom:** breaking a running gravity normalizer left gravity applied to its flood-filled positions; same silent bug for oxygen.
- **Root cause:** in MC 1.26.1, `LevelChunk.setBlockState` runs `removeBlockEntity` *before* `Block#affectNeighborsAfterRemoval`. `BasicEntityBlock` was calling `tickable.onRemoved()` from the latter, so `level.getBlockEntity(pos)` was always null.
- **Fix:** override `BlockEntity#preRemoveSideEffects` in `MachineBlockEntity` and route to `onRemoved()` — that hook fires *before* BE detachment.

### Cable network — solar→energizer never transferred
- **File:** `fabric/src/main/java/earth/terrarium/adastra/common/blockentities/pipes/CableBlockEntity.java`
- **Symptom:** wiring solar panel → cable → energizer did nothing.
- **Root cause:** `isProducer()` classified the energizer as a producer, then the `!isProducer` check in `addNode()` excluded it from consumers. The energizer was a source-only node with no sinks on the network.
- **Fix:** added `isBuffer()` for entities that should be both source and consumer; energizer now listed in both maps. `Pipe#transfer` already skips self-transfer, so this is safe.

### Glacian Ram — crash on Glacio
- **File:** `fabric/src/main/java/earth/terrarium/adastra/common/entities/mob/GlacianRam.java`
- **Symptom:** `IllegalArgumentException: Can't find attribute minecraft:tempt_range` every AI tick of a ram.
- **Root cause:** MC 1.21+ added `Attributes.TEMPT_RANGE`, and `TemptGoal#canUse` looks it up unconditionally. Vanilla animals get it via `Animal.createAnimalAttributes()` — this ram was built off `Mob.createMobAttributes()` and skipped the helper.
- **Fix:** added `.add(Attributes.TEMPT_RANGE, 10.0)` to the ram's attribute builder.

### Rocket UI — player inventory invisible
- **File:** `fabric/src/main/java/earth/terrarium/adastra/client/screens/base/VehicleScreen.java`
- **Symptom:** rocket GUI showed slot outlines but no items.
- **Root cause:** `VehicleScreen.extractContents` blitted the background but never called `super.extractContents`. In MC 1.21+, that super call drives slot/item/label rendering — `MachineScreen` already documents the same fix.
- **Fix:** chained `super.extractContents` after the background blit.

### HUD overlay — rocket countdown, lander brake prompt, etc. missing
- **File:** `fabric/src/main/java/earth/terrarium/adastra/client/fabric/AdAstraClientFabric.java`
- **Symptom:** no 3…2…1 rocket countdown, no lander descent prompt, oxygen bar and battery bar invisible.
- **Root cause:** `HudRenderCallback` was stubbed out with a TODO during the port. The render code in `OverlayScreen` was intact; nothing was calling it.
- **Fix:** registered via the new `HudElementRegistry.attachElementBefore(VanillaHudElements.CHAT, ...)`. Draws on top of gameplay HUD, under chat.

### Jet suit — multiple polish passes
- **File:** `fabric/src/main/java/earth/terrarium/adastra/common/items/armor/JetSuitItem.java` + `fabric/src/main/java/earth/terrarium/adastra/common/utils/KeybindManager.java`

**Collision in fullFlight space mode:**
- Hitting any block at speed used to dead-stop because vanilla zeroes the colliding velocity axis and base thrust (0.085) couldn't recover quickly.
- Fix: thrust bumps to `0.6` while `horizontalCollision || verticalCollision`. Slides along walls now, recovers in ~3 ticks instead of ~20.

**upwardsFlight in space — coast slowdown gone:**
- Old code applied always-on `0.995` damp (~10%/sec) even mid-coast.
- Fix: damp = `1.0` when not touching anything; `0.99` only when in contact. GravityApi's `SPACE_FRICTION=0.999` handles natural coast decay (barely perceptible).
- Capped at `1.8` b/tick (matches fullFlight) so unlimited thrust doesn't blow past the design speed.

**WASD support — A/S/D now work, not just W:**
- Input direction computed in world space via vanilla's `getInputVector` yaw rotation: `(xxa * cosYaw - zza * sinYaw, _, zza * cosYaw + xxa * sinYaw)`, normalized so diagonal isn't 1.41× cardinal.
- Replaces previous "always thrust in look direction" with "thrust in actual WASD direction." Atmospheric mode also got the same treatment.

**Tap-to-burst — taps now feel like real pulses:**
- `KeybindManager.set()` compares prev/current jumpDown and sets a `jumpPressedThisTick` flag on rising edge.
- `upwardsFlight` reads it and adds `+0.25` y impulse and `+0.15` horizontal impulse (in input dir) once per press.
- Sustained holds are unchanged (impulse fires once); rapid press-release-press-release now builds noticeable velocity instead of single-tick thrust.

### Dimension types — `/time set` no longer errors
- **Files:** `fabric/src/main/generated/resources/data/ad_astra/dimension_type/*.json` (all 11)
- **Symptom:** `/time set day` in orbit dims → "There is no default clock in dimension ad_astra:earth_orbit".
- **Fix:** added `"default_clock": "minecraft:overworld"` to all 11 dim types. Matches vanilla overworld semantics.

### Battery slot icon — magenta/black missing texture
- **File:** moved `fabric/src/main/resources/assets/ad_astra/textures/item/icons/battery_slot_icon.png` → `fabric/src/main/resources/assets/ad_astra/textures/gui/sprites/item/icons/battery_slot_icon.png`
- **Root cause:** MC 1.21+ builds the GUI sprite atlas only from files under `textures/gui/sprites/`. The identifier `ad_astra:item/icons/battery_slot_icon` was looking up a sprite that wasn't in the atlas.
- **Fix:** moved the PNG into the expected atlas tree. No code change needed.

### Jupiter storms — design decided (task #9–#12), key gotcha found
- **Per-dimension weather gotcha:** MC weather is effectively GLOBAL — non-overworld
  ServerLevels use `DerivedLevelData` that delegates rain/thunder to the overworld, and
  only the overworld advances the weather cycle. So `jupiterLevel.setWeatherParameters(...)`
  / `isThundering()` would read/write the shared (overworld) weather, NOT per-Jupiter.
  → **Do NOT base Jupiter storms on vanilla per-level weather.** Use a custom
  per-dimension storm state instead.
- **Plan:** custom `PlanetStormHandler` (server), state per storm-dimension (storming,
  intensity, nextTransitionTick, manualHoldUntil), ticked via the same pattern as
  `AtmosphereLeaveTicker` (a static `onServerTick(MinecraftServer)` registered at the
  Fabric server-tick entrypoint — find where AtmosphereLeaveTicker.onServerTick is
  registered and add alongside). Scheduler: ~85% storm→storm, storms 1–5 MC days, calm
  ~0.5–1.5 days rare; flag a "transition incoming" window for the visor alert.
- **`/weather` control:** since vanilla weather is global, redirect it: mixin into
  `net.minecraft.server.commands.WeatherCommand` (or register a sibling command) so that
  when the command source's level is a storm planet, `/weather clear|rain|thunder [dur]`
  sets the custom Jupiter storm state (clear=calm, rain/thunder=storm) with
  `manualHoldUntil = now + dur` and cancels the vanilla overworld change. After the hold
  expires the auto-scheduler resumes (so a `/weather clear 600` gives a calm window, then
  it storms again).
- **Wind physics:** apply CLIENT-SIDE on the local player (like `GravityApiImpl.entityTick`,
  which runs on the authoritative local instance) — read synced storm state, add a gusting
  horizontal impulse each tick (drifting wind dir + sine gusts × intensity, stronger when
  airborne). Players are client-authoritative, so server `setDeltaMovement` won't stick;
  do it where Ad Astra already does custom movement. Other entities: server push + motion packet.
- **Sync:** add an S2C packet (mirror an existing clientbound packet in
  common/network/packets/ + register in NetworkHandler) broadcasting storm state to players
  in the dimension on change + on join/dimension-change. Needed for wind + the visor HUD.
- TODO still also: Analysis Visor workbench upgrade (#11) + storm HUD alerts (#12).

### Jet suit ignored Jupiter gravity — root cause + fix
- **Bug:** `LivingEntityMixin.adastra$travel` skipped Ad Astra planet gravity whenever
  `entity.isFallFlying()`. `JetSuitItem.fullFlight()` (sprint+jump boost) calls `startFallFlying()`,
  so the boost flew with vanilla Earth-like elytra physics on *every* planet. (`upwardsFlight`,
  jump-only, never fall-flies, so it already respected gravity.)
- **Fix (scoped):** apply the gravity differential during fall-flight **only for jet-suit wearers**
  (`entity instanceof Player && chest.is(ModItemTags.JET_SUITS)`); plain vanilla elytra stays
  Earth-like. `getGravity()` is normalized (EARTH_GRAVITY=9.807 → Jupiter ≈2.53, Moon ≈0.165), so the
  net is heavy on Jupiter, floaty on the Moon, **unchanged on Earth** (term = 0.08-0.08 = 0).
- Note: this composes with vanilla elytra's own (modulated) gravity — directionally correct
  (heavy/floaty), not a pure linear scale. If Jupiter feels *too* hard to fly, scale jet thrust up
  with gravity (in `JetSuitItem.fullFlight`/`upwardsFlight`) for hard-but-possible. Not done yet.
