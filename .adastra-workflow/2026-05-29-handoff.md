## 1. Recipe "empty ingredients" load warnings — FIXED (JEI display)
- **Root cause:** `NasaWorkbenchRecipe`, `AlloyingRecipe`, `CompressingRecipe`,
  `CryoFreezingRecipe` all returned `PlacementInfo.NOT_PLACEABLE` from `placementInfo()`,
  so vanilla's placement system + JEI saw no ingredients → "Recipe … can't be placed
  due to empty ingredients" spam, and JEI wouldn't display the rocket/compressor/
  alloying/cryo recipes.
- **Fix:** return `PlacementInfo.create(ingredients)` (List recipes: NasaWorkbench, Alloying)
  / `PlacementInfo.create(ingredient|input)` (single-ingredient: Compressing, CryoFreezing).
  Signatures javap-verified against the 26.1 jar. Recipes craft exactly as before;
  this only exposes the ingredient list for display/recipe-book.
- **Left as-is (correct):** `RefiningRecipe`/`OxygenLoadingRecipe` stay `NOT_PLACEABLE` —
  they use `SizedFluidIngredient`, not item `Ingredient`.

## 5. Space-suit first-person hands (#10) — IMPLEMENTED (new hook)
- **Why the stub existed:** in 26.1 `PlayerRenderer` → `AvatarRenderer`, and `AvatarRenderer` has
  **no** `renderHand` on its public API — first-person hand rendering moved to the private
  `AvatarRenderer#renderHand(PoseStack, SubmitNodeCollector, int, Identifier, ModelPart arm, boolean slim)`
  (called from `renderRightHand`/`renderLeftHand`). The old `PlayerRendererMixin` was a dead no-op
  `@Mixin(AvatarRenderer.class)`.
- **Fix:** `PlayerRendererMixin` now `@Inject(method="renderHand", at=HEAD, cancellable)`. For the local
  player wearing a `SpaceSuitItem` (non-null layer+texture): `ci.cancel()`, bake the suit layer, build
  `SpaceSuitModel`, pick the arm side via `arm == getModel().rightArm`, then **mirror vanilla's
  renderHand exactly** — `suitArm.resetPose(); visible=true; zRot = right ? 0.1f : -0.1f;` — and
  `collector.submitModelPart(suitArm, poseStack, RenderTypes.armorTranslucent(texture), light,
  NO_OVERLAY, null)`. First-person positioning comes from the pose stack, so resetPose (not copying the
  not-yet-reset arm transform) is what aligns the sleeve. (`ModelPart#copyFrom` was removed in 26.1.)
- Mixin stays registered as `client.PlayerRendererMixin` in `adastra-common.mixins.json`.
- **Known limitation:** dye tint is not applied to the first-person suit arm (`submitModelPart` has no
  color args). Suits are usually undyed; flag if a dyed suit looks wrong in first person.

  Tag JSON `data/ad_astra/tags/entity_type/ignores_planet_gravity.json` contains `ad_astra:blue_vex`.
