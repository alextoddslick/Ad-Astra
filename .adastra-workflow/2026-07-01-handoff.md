# 2026-07-01 — Session Handoff

## Jet suit flight reimplemented from 1.20.1 (user-confirmed "Literally Perfect")

User reported jet suit flight broken on the 26.2 branch and asked to reimplement the
original 1.20.1 flight. Root cause was architectural, introduced by the version ports:

- **1.20.1:** `Item#inventoryTick(Level, …)` ran on BOTH sides — the client applied its
  own flight velocity every tick → responsive flight.
- **26.x:** `Item#inventoryTick(ServerLevel, …)` is server-only. Flight was applied
  server-side with `hurtMarked = true` (per-tick velocity sync → rubber-banding), and
  the accreted custom steering physics read `player.zza/xxa` on the server, where WASD
  input is never populated for real players (silently 0).

### Changes
- **`JetSuitItem`** (`fabric/.../common/items/armor/JetSuitItem.java`):
  - Flight logic extracted into public `tickFlight(Player, ItemStack)`, called from the
    server `inventoryTick` AND from `AdAstraClient.clientTick` for the local player —
    restores the 1.20.1 dual-sided model. `consume()` still no-ops client-side, so
    energy drains once (server).
  - `upwardsFlight` / `fullFlight` replaced with the verbatim 1.20.1 physics
    (sigmoid vertical accel ÷25 min 0.0025; look-thrust 0.075 with 2.0 speed cap +
    `startFallFlying` glide). All the custom turn-assist / WASD-thrust / tap-impulse /
    damping code from the 26.1.x rounds is GONE.
  - Kept (layered on, own gates, don't affect default feel): boost ×2.5 multiplier on
    >15 m/s² worlds, boost-boots sneak-hover, space brake (sneak against block in space),
    atmosphere-leave. Removed `hurtMarked` from hover/brake (both sides run the logic now).
  - `KeybindManager.jumpPressedThisTick` is now unused (left in place, harmless).
- **`AdAstraClient.clientTick`**: calls `suit.tickFlight(player, chest)` next to the
  existing particle call (runs at START_CLIENT_TICK — same tick phase as 1.20.1's
  inventoryTick).
